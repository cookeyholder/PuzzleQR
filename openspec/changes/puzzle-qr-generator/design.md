## Context

本系統為純客戶端運行的獨立網頁應用程式，不依賴後端伺服器或繁複的打包構建工具。設計動機詳見 `proposal.md`。系統整合輕量級純 JavaScript QR Code 編碼與解碼核心，並搭配雙層 HTML5 Canvas 渲染管線，旨在提供兼具高度趣味性與手機相機秒掃相容性的可玩迷宮。

## Goals / Non-Goals

**Goals:**
- 純 Vanilla JS 原生架構，零打包工具依賴（無 Webpack/Vite 負擔），可直接在任何現代瀏覽器中開啟運行。
- 透過強制使用 QR Version 4+（至少 33x33 網格）與 Level H 容錯等級（30% 損壞復原能力），確保迷宮路徑具備充足的探索空間與強韌的讀取相容性。
- 採用雙層 Canvas 分離架構（底層靜態迷宮 + 頂層 60 FPS 軌跡互動層），確保在手機觸控與滑鼠操作下均能維持極致滑順的畫線體驗。
- 實作智慧加權 A* 尋路與安全打通機制，在嚴格限制的修改預算內打通外緣出入口，保證迷宮 100% 可解且不損壞 QR Code 讀取率。
- 內建瀏覽器記憶體虛擬解碼驗證儀，在生成後立即檢測並呈現相容性綠燈指示。
- 支援 PNG 與原生向量 SVG 格式輸出，具備自訂檔名與未解/破關雙模式支援。

**Non-Goals:**
- 不建置後端伺服器、使用者資料庫、雲端存檔或數據追蹤服務。
- 不引入聲音合成器或音效播放（維持純粹的視覺美感與觸摸操作）。
- 不在 QR Code 中央硬塞破壞性圖標或未經驗證的巨幅 Logo，避免影響光學掃描辨識率。

## Decisions

### 1. 雙層 Canvas 疊合架構 (Dual-Layer Canvas Architecture)
- **決定**：使用兩個由 CSS 絕對定位重疊的 `<canvas>` 畫布：
  - 底層畫布 (`#mazeCanvas`)：負責繪製主題背景、四周外牆護城河、融合後的長短迷宮牆壁以及起點/終點開口。僅在使用者變更內容或切換主題時重繪。
  - 頂層互動畫布 (`#gameCanvas`)：透明背景，負責監聽 pointer 事件、繪製使用者當前探索軌跡、提示光暈與通關粒子。在 `pointermove` 時高頻重繪。
- **理由**：將繁重的迷宮幾何線條渲染與玩家高頻拖曳互動完全隔離，確保即使在效能較弱的行動裝置上也能維持穩定的 60 FPS 手感。
- **替代方案評估**：單一 Canvas 每幀全畫面重繪（在行動裝置上拖曳時容易出現微幅掉幀與發熱）。

### 2. 連續模組長短線條融合演算法 (Run-Length Module Fusion)
- **決定**：遍歷 QR 二值矩陣，將水平或垂直連續相鄰的黑色單元格整合為長度為 $N$ 的線段描述符。繪製時採用圓角筆刷（`lineCap = 'round'`），筆刷寬度設定為單元格寬度的 75%~85%。
- **理由**：呈現連貫且具備長短變化的迷宮實體牆壁外觀，同時確保所有黑色模組的幾何中心點均保持 100% 的黑色飽和度，符合光學掃描器二值化取樣標準。
- **替代方案評估**：單純繪製 1x1 方塊（看起來仍是普通 QR Code，缺乏迷宮氛圍）；多邊形布林運算（在純 Vanilla JS 中計算負擔過重且效益有限）。

### 3. A* 加權尋路與安全 ECC 容錯預算打通 (Carving with ECC Budget)
- **決定**：在左上方外緣留白區開設入口，在右下方外緣開設出口。執行加權 A* 尋路演算法（白色通道移動成本為 1，穿透黑牆成本為 100）。若起點至終點被黑牆截斷，演算法自動挑選穿透代價最低的路徑，將關鍵黑牆轉為白格打通，並嚴格將修改模組總數限制在總模組量的 8% 以內。
- **理由**：Level H 允許高達 30% 的模組失真，8% 的修改預算能在 100% 保證可通行的前提下，為真實相機取樣的陰影、反光留出足夠的容錯餘裕。
- **替代方案評估**：隨機種子窮舉搜尋（對於固定的使用者網址無法隨意加入參數時會失效）；無預算隨機打洞（極易超出糾錯極限導致無法讀取）。

### 4. 走道中心磁吸軌道與軌跡堆疊倒退 (Center-Snap Rails & Auto-Backtracking)
- **決定**：將使用者的指針移動映射至離散網格座標。當指針在走道移動時，路線以平滑內插線段吸附至走道中心；若移動方向為相鄰黑牆，則限制指針穿透。軌跡以陣列堆疊維護，當偵測到指針逆向移動回倒數第二個走道時，自動 pop 彈出並清除末端線條。
- **理由**：徹底消除玩家因滑鼠微手震或手指過粗觸碰牆壁導致的挫折感，讓探索死巷與原路折返如同貪食蛇般直覺流暢。
- **替代方案評估**：自由像素手繪與剛性碰撞（挫折感極高，容易因為像素級擦碰被判定失敗）。

### 5. 基於向量幾何描述的原生 SVG 匯出 (Vector SVG Generation)
- **決定**：將牆壁線段、背景矩形與出入口標記維護為乾淨的幾何資料結構，匯出 SVG 時直接組裝標準 XML `<svg><path d="..." /></svg>` 字串。
- **理由**：產出的向量圖檔體積小巧（通常小於 20KB）、無失真縮放，可直接用於專業印刷排版、雷射雕刻或割字機製作實體迷宮道具。
- **替代方案評估**：將 Canvas 點陣圖轉為 Base64 嵌入 SVG（並非真正的向量圖，放大列印仍會模糊失真）。

## Risks / Trade-offs

- **[風險：深色或低對比主題可能導致相機掃描困難]**
  - *緩解措施*：所有內建主題（包括 Cyber 賽博風格）均嚴格確保牆壁顏色與走道底色具有大於 4.5:1 的明度對比度，且背景色均為大面積均勻色。
- **[風險：打通演算法誤觸破壞關鍵尋標圖案 (Finder Patterns)]**
  - *緩解措施*：在 A* 尋路圖中，將三個角落的 7x7 尋標圖案、第 6 列/行的時序線（Timing Pattern）設為不可穿透的絕對障礙（成本設為無限大）。
- **[風險：手機觸控螢幕滑動手勢觸發瀏覽器下拉刷新或頁面捲動]**
  - *緩解措施*：在互動畫布上套用 CSS `touch-action: none`，並統一使用 Pointer Events API（`pointerdown`, `pointermove`, `pointerup`）。
